A stack is a good choice for an undo and redo system because it follows
the Last In, First Out structure. The most recent action performed by the
user should also be the first action that gets undone. In my program, each
action is added to the top of the undo stack. When the user selects undo,
that action is removed from the undo stack and moved to the redo stack.
This also makes redo work naturally because the most recently undone
action is the first one that should be restored.

A queue works better for the help desk because it follows First In, First
Out. In a normal help desk, the customer who has been waiting the longest
should usually be helped first. New customers are added to the rear of the
queue, while the next customer being helped is removed from the front.
This keeps customers in the same order that they entered the system.

My stack and queue are different from Python's built-in lists because I
created the data structures myself using nodes and pointers. Each node
stores a value and a reference to the next node. The stack keeps track of
the top node, while the queue keeps track of both the front and rear nodes.
Python lists already provide built in methods for adding, removing, and
accessing items. Building these structures manually requires more code,
but it helped me understand what is happening behind operations like push,
pop, enqueue, and dequeue.
